# Open Source Protocol Layer — Design Spec

**Date:** 2026-09-20  
**Status:** Approved — implementation in progress  
**Author:** Tashfeen Ekram

---

## Overview

Extract all protocol content from `src/data/protocols.ts` in the `huberman-protocol-pal` app into a standalone, community-editable npm package (`@protocol-pal/protocols`). The app becomes an engine that _implements_ protocols defined externally; the community owns the protocol content.

The protocols (triggers, actions, science, frequency rules) are the extractable, shareable knowledge layer. The app is the delivery engine. This split lets other tools, apps, or researchers use the protocol definitions independently.

---

## Goals

- Protocol content (definitions, triggers, science, actions) lives in a separate **public** GitHub repo
- Community can submit PRs to add/edit protocols without touching app code
- App consumes protocols as a **versioned npm package** (pinned, offline-safe, no runtime fetch)
- TypeScript types + JSON Schema serve as the contract between data and app
- BLE ring scoring model repo can reference the same protocol schema for trigger metric definitions

## Non-Goals

- Runtime fetching of protocols (handled by versioned npm releases)
- Backend/database (protocols remain static JSON)
- Protocol personalization engine (stays in app)
- Changing app UX (this is purely a data layer refactor)

---

## Architecture

### New Repo: `tekram/huberman-protocols`

- **License:** MIT
- **Format:** One JSON file per protocol in `protocols/` directory
- **Schema:** `schema/protocol.schema.json` (JSON Schema v7)
- **Index:** `dist/index.json` — flat array of all protocols, generated by build script
- **Validation CI:** GitHub Actions runs `ajv` against schema on every PR
- **Package:** Published to npm as `@protocol-pal/protocols`

### App Changes (`huberman-protocol-pal`)

- Remove data from `src/data/protocols.ts`, keep file only as type re-exports
- Move interfaces to `src/types/protocol.ts`
- Add `@protocol-pal/protocols` as npm dependency
- Import JSON: `import protocols from '@protocol-pal/protocols'`
- Add Zod validation at app startup to catch schema drift early

## TypeScript Interfaces (source of truth for schema)

These live in the app at `src/data/protocols.ts` and drive the JSON Schema:

```typescript
export type ProtocolImportance = 'foundation' | 'high-impact' | 'supplemental';

export interface OuraTrigger {
  metric: 'sleep_score' | 'readiness_score' | 'hrv' | 'resting_hr'
        | 'activity_score' | 'temperature_deviation';
  operator: '<' | '>' | '<=' | '>=';
  threshold: number;
  label?: string; // e.g. "sleep < 75"
}

export interface Protocol {
  // Required
  id: string;
  title: string;
  frequency_type: 'daily' | 'weekly' | 'conditional';

  // Optional metadata
  description?: string;
  category?: string;
  duration?: string;
  difficulty?: 'beginner' | 'intermediate' | 'advanced';
  priority?: number;          // lower = higher priority
  importance?: ProtocolImportance;
  source?: string;
  last_updated?: string;

  // Scheduling
  oura_triggers?: OuraTrigger[];
  weekly_frequency?: {
    times_per_week: number;
    preferred_days?: ('monday'|'tuesday'|'wednesday'|'thursday'|'friday'|'saturday'|'sunday')[];
    min_rest_days?: number;
  };
  conditional?: {
    question: string;
    yesLabel?: string;
    noLabel?: string;
  };

  // Content
  actions?: {
    action: string;
    duration: string;
    frequency: string;
    timing: string;
    details: string;
  }[];
  benefits?: string[];
  science?: string;
  contraindications?: string[];
  estimated_impact?: Record<string, string>;
  learning_resources?: {
    title: string;
    type: 'video' | 'webpage' | 'article';
    url: string;
    duration?: string;
  }[];
}
```

## Community Workflow

1. Fork `tekram/huberman-protocols`
2. Add/edit protocol JSON in `protocols/`
3. CI validates against `schema/protocol.schema.json`
4. PR reviewed, merged → CI rebuilds `dist/index.json`, publishes new npm version
5. App maintainer bumps `@protocol-pal/protocols` dependency to pick up new protocols

## Version Strategy

| Bump | When |
|------|------|
| `major` | Breaking schema change (field removed, type changed) |
| `minor` | New protocols added |
| `patch` | Edits to existing protocol content |

---

## Risks

- **Schema drift:** App Zod validation catches mismatches at startup before they reach users
- **npm publish automation:** Start manual (maintainer runs `npm publish`), add `semantic-release` later
- **Protocol quality:** CONTRIBUTING.md must specify sourcing requirements (Huberman Lab citations only)
- **BLE ring integration:** `oura_triggers` metric names must stay in sync with ring scoring model — document this dependency clearly

## Decision Log

| Decision | Rationale |
|----------|----------|
| npm package, not runtime fetch | Mobile offline-safety; no CDN dependency |
| One JSON file per protocol | Easier PR reviews, less merge conflict surface |
| JSON Schema v7 + ajv in CI | Industry standard, fast, no extra dependencies |
| Zod in app | Runtime safety without bundling ajv in mobile app |
